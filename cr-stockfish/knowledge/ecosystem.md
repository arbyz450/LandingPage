# Clash Royale automation / vision ecosystem survey (as of 2026-11-21)

Items marked **[unverified]** lack a primary source: in this session only github.com and developer.android.com could be fetched directly; supercell.com, support.bluestacks.com, support.google.com, universe.roboflow.com, fandom and royaleapi.com were blocked, so those facts come from search-result excerpts.

## (a) Pbatch/ClashRoyaleBuildABot — https://github.com/Pbatch/ClashRoyaleBuildABot

- **What it is:** "advanced state generator" + bot, 388 stars, 562 commits, active; Python `==3.12.*`, uv install; topics yolov10, adb, bluestacks.
- **License:** MIT (LICENSE.md, "Copyright (c) 2022 Peter Batchelor"). The ONNX weights are committed in the repo under the same license: **the detector weights are publicly downloadable under MIT**.
- **Detectors shipped** (`clashroyalebuildabot/detectors/`):
  - `unit_detector.py` — ONNX object detector (`OnnxDetector` base, onnxruntime CPU or CUDA EP, float16 input, letterbox pad 114, /255). Crops the screenshot to y ∈ [5%, 80%] of height, `MIN_CONF = 0.3`. Model: `clashroyalebuildabot/models/units_M_480x352.onnx` (29.5 MB in git; input 480x352, shape read from the model). Release notes mention YOLOv8 then YOLOv5, the topic says yolov10 — current architecture **[unverified]**.
  - `side_detector.py` + `models/side.onnx` — small binary CNN that classifies a detection crop as ally vs enemy (only applied to units that could be in your own deck).
  - `card_detector.py` — **not** a neural net: perceptual hash (8x8 grayscale, three brightness variants) of each hand slot against `images/cards/<card>.jpg`; hand size 5 incl. blank.
  - `number_detector.py` — no model: elixir from the elixir bar via rolling std-dev; princess-tower HP as a 0..1 fraction from HP-bar pixel colours (`NUMBER_CONFIG`). README lists an "HP detector fix" as upcoming.
  - `screen_detector.py` — screen state via an external "OneJev" model server at `http://localhost:8000` (default_config.yaml).
- **Class list (`DETECTOR_UNITS`, 101 classes):** archer, archer_queen, balloon, bandit, barbarian, barbarian_hut, bat, battle_healer, battle_ram, bomb_tower, bomber, bowler, brawler, cannon, cannon_cart, dark_prince, dart_goblin, electro_dragon, electro_giant, electro_spirit, electro_wizard, elite_barbarian, elixir_collector, elixir_golem_large/medium/small, executioner, fire_spirit, firecracker, fisherman, flying_machine, furnace, giant, giant_skeleton, giant_snowball, goblin, goblin_cage, goblin_drill, goblin_hut, golden_knight, golem, golemite, guard, heal_spirit, hog, hog_rider, baby_dragon, hunter, ice_golem, ice_spirit, ice_wizard, inferno_dragon, inferno_tower, knight, lava_hound, lava_pup, little_prince, lumberjack, magic_archer, mega_knight, mega_minion, mighty_miner, miner, minion, minipekka, monk, mortar, mother_witch, musketeer, night_witch, pekka, phoenix_egg/large/small, prince, princess, ram_rider, rascal_boy, rascal_girl, royal_ghost, royal_giant, royal_guardian, royal_hog, royal_recruit, skeleton, skeleton_dragon, skeleton_king, sparky, spear_goblin, tesla, tombstone, valkyrie, wall_breaker, witch, wizard, x_bow, zappy. No 2024+ cards, evolutions or heroes are present.
- **Training data:** wiki "Object Detection Data" links two Google Drive archives (`units.tar.gz`, `numbers.tar.gz`, YOLOv5 format); counts/license not stated. Roboflow project `peter_batchelor1-hotmail-com/clashroyaleunits` also exists **[unverified]**.
- **Emulator / ADB:** `adb -s <serial>` (default `emulator-5554`); auto-downloads `platform-tools-latest-<os>.zip` from dl.google.com. Capture is a continuous `adb shell screenrecord --output-format=h264` stream (179 s segments, 5 Mbps) decoded with PyAV; taps are `adb shell input tap`; size via `adb shell wm size`.
- **Expected resolution:** `DISPLAY_WIDTH/HEIGHT = 720x1280`, frames downscaled to `SCREENSHOT_WIDTH/HEIGHT = 368x652`; tile grid 18x15, `TILE_WIDTH 34`, `TILE_HEIGHT 27.6`, origin (52, 296); hand card boxes at y=543, x=84 + i*69, 61x73 px (screenshot space).
- **Emulator Setup Guide** (docs/emulator-setup.md + wiki): Android 9 Pie 64-bit, 4 cores, 4 GB RAM, portrait **720x1280 @ 240 DPI**. Only BlueStacks is documented: Settings > Display > Portrait 720x1280; Settings > Advanced > enable Android Debug Bridge; disable ads; install CR from Play Store, finish tutorial, English. LDPlayer 9, MEmu and the Play Games Developer Emulator are "details to be added". No ADB port given.
- **Releases:** v1.0.0 … v1.3 carry only source archives; weights ship in the repo.
- README disclaimer: use with Clash Royale violates Supercell ToS and risks a ban.

## (b) pyclashbot/py-clash-bot — https://github.com/pyclashbot/py-clash-bot

- **Approach:** classical image recognition on OpenCV screenshots (no ML); 340 stars, 2,394 commits; Windows + macOS installers. Plays ladder/2v2 with random/cycled card plays and does chest/upgrade/donate/pass chores and multi-account rotation.
- **Emulators:** MEmu (Windows only, controlled via `PyMemuc`/`memuc`, creates VM "pyclashbot-136" = Android 13 64-bit, **419x633 @ 160 DPI**, 2 CPU/2 GB, DirectX or OpenGL), BlueStacks 5 (Windows/macOS; reads the instance ADB port from `bluestacks.conf`, runs `HD-Adb`/`hd-adb` on a private server port 5041, sets 419x633/160 DPI, Vulkan on macOS; "must be BlueStacks 5, not X/10"), Google Play Games **developer** emulator (Windows only, `adb connect localhost:6520`, `wm size 419x633`), and generic ADB devices (`host:port`, `emulator-N`, USB serial).
- **I/O:** screenshots `adb exec-out screencap -p` (MEmu: `screencap -p | base64`); input `adb shell input tap/swipe`.
- **License:** source under "py-clash-bot Non-Commercial Copyleft License 1.0" (NC-CL-1.0, share-alike, non-commercial); assets/reference images under CC BY-NC-SA 4.0. **Not** permissively reusable.

## (d) Emulator / device facts (2026)

- **BlueStacks 5 (Windows):** Settings > Advanced > toggle "Android Debug Bridge" > Save; the panel shows `adb connect 127.0.0.1:<port>`. First instance is usually **5555** but can differ — read it from the panel or `bluestacks.conf` (`bst.instance.<name>.status.adb_port`) as py-clash-bot does. Bundled `HD-Adb.exe`. Article: https://support.bluestacks.com/hc/en-us/articles/23925869130381. BlueStacks X/10 (cloud) is unusable.
- **LDPlayer 9:** Settings > Others > "ADB debugging" > Open local connection; `adb connect 127.0.0.1:5555`; multi-instance ports follow `5555 + 2*index` (official ldconsole guide: https://www.ldplayer.net/support/ldplayer-ldconsole-command-line-developer-usage-guide.html).
- **MEmu:** ADB on by default, `adb connect 127.0.0.1:21503` for the first instance (+10 per instance) — community-documented (Airtest docs), **[no official page found]**; `memuc` CLI gives screencap/adb/keystroke without the port.
- **Google Play Games on PC:** the **consumer** client exposes no ADB **[unverified; inferred]**. The **Developer Emulator** (https://developer.android.com/games/playgames/pg-emulator) appears as `localhost:6520`, supports normal `adb shell`/screencap/screenrecord, cannot run alongside the consumer client, defaults to 16:9 (9:16 selectable), Windows only. py-clash-bot drives it at `wm size 419x633`.
- **Android Studio emulator:** x86_64 images translate ARM code only on Android 11+ Google APIs/Play Store images (https://android-developers.googleblog.com/2020/03/run-arm-apps-on-android-emulator.html), slowly and "for debugging only". Whether Clash Royale ships x86_64 libs is **[unverified]**; if ARM-only it needs a translating Play image or an arm64 image on an Apple Silicon/ARM host, where ARM apps run natively. ADB is the usual `emulator-5554`.
- **macOS:** BlueStacks Air (macOS 11+, Apple Silicon M1–M4; https://www.bluestacks.com/mac). Its docs do not mention ADB, but py-clash-bot's macOS path uses `/Applications/BlueStacks.app/.../hd-adb` plus the port from `/Users/Shared/Library/Application Support/BlueStacks/bluestacks.conf`, implying ADB works **[unverified]**. Google Play Games is Windows-only. Alternatives: Android Studio arm64 emulator (native), MuMuPlayer Pro for Mac (paid, advertises ADB) **[unverified]**.
- **Real Android phone:** Developer options > USB debugging; Wi-Fi via `adb tcpip 5555` + `adb connect <ip>:5555`, or Android 11+ Wireless debugging pairing. **scrcpy** v5.0 (5 Oct 2026) / v5.0.1 (8 Oct 2026, https://github.com/Genymobile/scrcpy/releases): platform-tools 37.0.1, Android 5.0+, 35–70 ms mirroring latency, GPU decoding, `--tcpip[=ip[:port]]`, `--otg`/`--keyboard=uhid`, `--no-playback` for headless control. `adb shell input tap` spawns a Java process per call: **~100–300 ms** per tap (>1 s on old devices); a persistent `adb shell`, scrcpy's control socket or minitouch (DeviceFarmer fork) reaches ~5–20 ms **[community figures]**. `adb exec-out screencap -p` ≈ 100–300 ms/frame; `screenrecord`/scrcpy video gives 30–60 fps.

## (e) Platform constraints

- **iOS without jailbreak: no.** Third-party apps are sandboxed with no API to read another app's screen or inject touches; App Store "auto clickers" only replay Switch Control/AssistiveTouch gestures blindly (https://positioniseverything.net/is-there-an-autoclicker-for-ios-everything-you-need-to-know/). The sole non-jailbreak path is tethered XCTest via WebDriverAgent/Appium (https://github.com/appium/WebDriverAgent): Mac + Xcode + signing, hundreds of ms per tap/screenshot, not an on-device product, still a ToS violation. Apple docs unreachable here **[primary citation missing]**.
- **On-device Android "auto-play" app:** technically feasible without root — `MediaProjection` capture (per-session consent on Android 14+) plus an `AccessibilityService` calling `dispatchGesture()` (API 24+). **Play Store:** not allowed for game automation. The AccessibilityService policy (https://support.google.com/googleplay/android-developer/answer/10964491) allows only narrow, disclosed, user-initiated automation and lists "automation tools" as non-accessibility uses needing declaration; Device and Network Abuse bans apps that interfere with other apps and "game cheating apps that affect the gameplay of other apps" (https://support.google.com/googleplay/android-developer/answer/9888379 **[URL from memory]**). Generic auto-clickers survive; a Clash Royale bot would be removed, leaving sideloading.

## (f) Supercell policy

- **Terms of Service** (https://supercell.com/en/terms-of-service/en, current version dated 2024-11-06 per search results): users may not "use cheats, exploits, automation software, emulators, bots, hacks, mods or any unauthorized third-party software designed to modify or interfere with the Service", nor modify game files. Note that emulators themselves are listed.
- **Safe and Fair Play policy** (https://supercell.com/en/safe-and-fair-play/): defines third-party software as unapproved apps that manipulate gameplay; "using prohibited third-party software to gain an advantage will result in a permanent ban"; applies to all Supercell games including Clash Royale.
- Clash Royale support "Don't Be a Cheat": https://support.clashroyale.com/hc/en-us/articles/49484901806747-Don-t-Be-a-Cheat (bots and mods are cheating; heavy account penalties). Supercell's 2024 Clash of Clans post documents mass permanent bans of bot accounts: https://supercell.com/en/games/clashofclans/blog/misc/update-to-our-fair-play-policy-and-next-steps.
- Implication: any live-account bot (both projects above say so) risks a permanent ban; offline analysis of recordings/replays does not touch the service.
